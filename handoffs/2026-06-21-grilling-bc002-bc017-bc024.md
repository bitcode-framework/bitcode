## What Was Done

Grilling session challenged the 3 bugs that were marked as "cannot fix in this phase" by the previous AI session. Each bug was investigated against the actual source code, compiled output, ADRs, and CONTEXT.md.

### BC-002 (BcInput slotProps.label attributes) — Bug log corrected, defer to Phase B remains

**Finding:** Original bug log claimed "Mitosis can't spread `{...partAttr()}`" and classified as architecture change. This was inaccurate. ADR-009 already documents that dynamic spread is not supported (deliberate multiplatform decision) and the design solution (`partAttr` single-attr accessor) already exists. `BcInput.lite.tsx` imports `partAttr` but never calls it — the wiring simply hasn't been done.

**Action:** Corrected bug log to accurately describe the issue as "partAttr wiring not yet implemented; design solution exists in ADR-009". No code change needed. Defer to Phase B remains correct (audit per-component).

### BC-017 (BcSplitter pointer drag) — Split into BC-017a (wontfix) + BC-017b (fixed)

**Finding:** Original bug log bundled two issues into one wontfix. (a) jsdom pointer-event limitation (fireEvent.pointerMove delivers undefined clientX, getBoundingClientRect returns zeros) — genuine wontfix. (b) stale-state closure on `dragging` flag — same pattern as BC-015/BC-019 which were already fixed.

**Action (BC-017b fix):** Added `draggingRef = useRef<boolean>(false)` in `BcSplitter.lite.tsx`. `startDrag`/`stopDrag`/`onMove` read from `draggingRef` (always current) instead of `state.dragging` (stale in closure). `state.dragging` remains for render. Updated source test to match new pattern. Runtime test verifies `onMove` ran (onResize called).

### BC-024 (BcReactiveScope onChange) — Split into BC-024a (deferred to A3) + BC-024b (fixed)

**Finding:** Original bug log only mentioned test-timing and suggested useRef as "possible fix". Deeper investigation found a **production memory leak**: the `useEffect` cleanup (deps `[]`) captured `scopeOff` from the first render (null), so `unsubscribe` was never called on unmount. With externally-owned stores, the listener leaked. `BcForm` and `AppProvider` have the same pattern but are safe because they dispose the store on unmount.

**Action (BC-024b fix):**
1. Added `unsubscribe(listener)` method to `ReactiveStore` (symmetric with `subscribe`, mirrors DOM EventTarget pattern).
2. Refactored `BcReactiveScope.lite.tsx` to store listener in `useRef` (`changeListenerRef`) instead of `useStore` state. `useRef.current` is always current regardless of closure capture.
3. Removed `ScopeOff` type and `mkScopeOff` factory (no longer needed).
4. Added test "unsubscribes onChange listener on unmount" — verifies onChange NOT called after unmount with external store.
